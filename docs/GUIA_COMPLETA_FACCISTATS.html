1. Que resuelve FacciStats

FacciStats es una API REST para administrar personajes, cartas, eventos y usuarios de un catalogo galactico. Su funcionalidad propia transforma esos registros en estadisticas por faccion: personajes, vivos, muertos, cartas, poder promedio, eventos ganados y porcentaje de bajas.

Una API no es una pagina web comun: recibe solicitudes HTTP, consulta o modifica MySQL y devuelve JSON. Swagger es la interfaz que documenta y permite probar cada operacion desde el navegador.

ParteQue aportaUbicacion
CRUDCrear, leer, actualizar y eliminar personajes, cartas, eventos y usuarios.Controllers/PersonajesController.cs, CartasController.cs, EventosController.cs, UsuariosController.cs.
Componente propioFiltros, paginacion, ranking, comparacion y estadisticas por faccion.Controllers/FaccionesController.cs y Services/ApiService.cs, metodo Estadisticas().
PersistenciaEntidades almacenadas como tablas relacionales en MySQL.Data/AppDbContext.cs y Migrations/.
ProteccionSecretos fuera de Git, hash de contrasena y cifrado de datos sensibles.Program.cs, Services/CifradoService.cs, controladores de personajes y usuarios.

Conceptos esenciales

  • REST: una URL representa un recurso y el metodo HTTP expresa la accion: GET lee, POST crea, PUT actualiza y DELETE elimina.
  • Endpoint: combinacion de metodo y ruta, por ejemplo GET /api/v1/personajes.
  • JSON: formato estructurado de respuesta, por ejemplo {"id":1,"nombre":"Astra"}.
  • Entidad: clase que Entity Framework Core convierte en tabla.
  • DTO: objeto de entrada/salida que limita exactamente los datos que la API acepta o expone.
  • DI: inyeccion de dependencias: ASP.NET entrega un servicio al controlador sin que este lo construya manualmente.

4. Que ocurre en una peticion

Cliente o Swagger -> Controller -> Servicio cuando corresponde -> AppDbContext / EF Core -> MySQL -> JSON y codigo HTTP
  1. Swagger, un navegador o cliente HTTP envia una URL.
  2. ASP.NET encuentra el controlador por [Route(...)] y el metodo por [HttpGet], [HttpPost], etc.
  3. ASP.NET convierte el JSON a un Request DTO. [ApiController] hace que anotaciones como [Required] generen 400 cuando la entrada no es valida.
  4. El controlador ejecuta reglas de negocio: una carta, por ejemplo, exige un personaje existente.
  5. EF Core convierte operaciones LINQ en SQL y AppDbContext las ejecuta en MySQL.
  6. Si hay texto sensible, CifradoService cifra antes de guardar o descifra antes de responder.
  7. El resultado se serializa a JSON con un codigo HTTP adecuado.

Ejemplo completo: POST de personaje

Se implementa en Controllers/PersonajesController.cs, metodo Crear. Recibe PersonajeRequest, aplica Trim() a nombre/faccion, cifra la biografia si existe, ejecuta db.Add y SaveChangesAsync. Luego responde 201 mediante CreatedAtAction, que ademas aporta la URL para consultar al nuevo recurso. Antes de responder llama service.Map, por lo que la biografia vuelve descifrada al cliente.

AsNoTracking() aparece en muchas lecturas. Significa que EF Core no vigilara cambios de esos objetos: es apropiado y mas liviano cuando solo se van a mostrar. Para editar se usa FindAsync, que entrega una entidad seguida por el contexto; SaveChangesAsync guarda las modificaciones.

Relacion uno a muchos

Un Personaje (1) <--- tiene muchas ---> Cartas (N)

En Personaje, List<Carta> Cartas es la navegacion hacia sus cartas. En Carta, PersonajeId es llave foranea y Personaje navega al padre. En Data/AppDbContext.cs, dentro del bloque de Carta, HasOne(...).WithMany(...).HasForeignKey(...).OnDelete(DeleteBehavior.Restrict) establece la relacion. Restrict impide borrar un personaje que tiene cartas; el DELETE tambien lo detecta y responde 400.

Reglas de AppDbContext

El metodo OnModelCreating de Data/AppDbContext.cs fija maximos de longitud, obligatoriedad, email unico con HasIndex(x => x.Email).IsUnique(), password hash requerido y columnas de datos cifrados. Sus propiedades DbSet representan las tablas que EF Core administra.

6. Proteccion de datos, paso a paso

Secret Manager

La cadena de conexion y clave AES no aparecen en el repositorio. En Program.cs se obtiene ConnectionStrings:DefaultConnection; si no existe, lanza una excepcion con una indicacion clara. User Secrets la proporciona en Development. appsettings.json solo conserva configuracion publica.

Hash de contrasena

La contrasena no se cifra: se transforma en un hash no reversible. Program.cs registra IPasswordHasher<Usuario> con PasswordHasher<Usuario>. En Services/ApiService.cs, metodo CrearUsuario, se ejecuta usuario.PasswordHash = hasher.HashPassword(usuario, request.Password). En actualizacion, UsuariosController.Editar genera otro hash. El metodo privado ADto nunca devuelve password ni PasswordHash. En un futuro login se usaria VerifyHashedPassword.

Cifrado AES-GCM

Telefono y biografia se deben recuperar, por eso se cifran. Services/CifradoService.cs lee Cifrado:Clave, la decodifica desde Base64 y exige 32 bytes (AES-256). Cifrar genera un nonce aleatorio de 12 bytes, codifica el texto a UTF-8 y llama AesGcm.Encrypt. Guarda nonce + tag de 16 bytes + texto cifrado como Base64. Descifrar separa esos mismos segmentos y llama AesGcm.Decrypt; GCM verifica tambien que el contenido no fue alterado.

Uso exacto: PersonajesController.Crear/Editar cifra la biografia; ApiService.Map la descifra. UsuariosController.Crear/Editar cifra telefono; UsuariosController.ADto lo descifra para la respuesta.

Demostracion en MySQL: PasswordHash, Telefono y BiografiaSecreta no contienen el texto original. Demostracion en GET: la API muestra telefono/biografia en claro despues de descifrarlos. Esta diferencia evidencia proteccion en reposo.

Validacion y reglas

  • Dtos/Requests.cs exige campos, longitud, email, password minimo de 8 caracteres y poder entre 0 y 100000.
  • UsuariosController evita email repetido: 409 Conflict.
  • CartasController exige personaje existente: 400 si falta.
  • FaccionesController.Personajes controla pagina, tamano y estado.
  • PersonajesController.Eliminar protege integridad cuando hay cartas.

La logica de estas rutas vive en Controllers/FaccionesController.cs, reutilizando una sola fuente de calculo: Services/ApiService.cs, metodo Estadisticas(). Asi cada endpoint obtiene numeros consistentes.

Lectura de ApiService.Estadisticas()

  1. Carga personajes con cartas usando Include(x => x.Cartas) y carga eventos; ambos AsNoTracking.
  2. GroupBy(x => x.Faccion.Trim(), StringComparer.OrdinalIgnoreCase) agrupa por faccion, quitando espacios y sin importar mayusculas.
  3. grupo.Count() da personajes. Los dos Count sobre EstaMuerto dan vivos y muertos.
  4. Sum(x => x.Cartas.Count) suma cartas.
  5. SelectMany(x => x.Cartas) aplana listas; si hay cartas, Average(x => x.Poder) entrega el poder medio; si no, devuelve null.
  6. eventos.Count(...) cuenta ganadores por faccion.
  7. Math.Round(muertos * 100.0 / total, 2) da porcentaje con dos decimales; 100.0 obliga division decimal.
  8. OrderBy(x => x.Faccion) deja salida estable y legible.
{
  "faccion": "Orden Solar",
  "personajes": 2, "vivos": 1, "muertos": 1,
  "cartas": 2, "poderPromedio": 72.5,
  "eventosGanados": 1, "porcentajeMuertos": 50.0
}

El contrato se define en Dtos/Responses.cs, record FaccionDto.

10. Guion para defender el trabajo

Presentacion en orden

  1. Problema: el sistema administra un catalogo y genera indicadores de facciones.
  2. Arquitectura: controladores reciben HTTP, servicios concentran logica, EF Core accede a MySQL y DTOs limitan entradas/salidas.
  3. Modelo: cuatro entidades y relacion uno-a-muchos Personaje-Carta.
  4. Evolucion: dos migraciones: inicial y agregado de biografia cifrada.
  5. Seguridad: secretos fuera de repo, hash de password, AES-GCM para texto recuperable.
  6. Aporte: estadisticas, filtros, paginacion, ranking y comparacion.
  7. Prueba: Swagger para caso correcto, 400/404 y MySQL para contrastar cifrado/hash.
Pregunta probableRespuesta breve
Por que no guardar password normal?Una password no debe recuperarse. PasswordHasher guarda un hash con salt y la API no devuelve PasswordHash.
Por que cifrar telefono y no hashearlo?Debe poder mostrarse de nuevo. AES-GCM permite descifrar con la clave; un hash no.
Que aporta GCM?Ademas de ocultar, la etiqueta de autenticacion detecta si el dato cifrado fue manipulado.
Donde esta la clave?En Secret Manager local, nunca en Git ni appsettings.json.
Que hace una migracion?Versiona el esquema: la primera crea tablas y la segunda agrega una columna; database update las aplica en orden.
Como se relacionan Carta y Personaje?Por PersonajeId, llave foranea configurada en AppDbContext.OnModelCreating y navegaciones de las entidades.
Que diferencia hay entre 400, 404, 409 y 201?400 solicitud invalida; 404 no existe; 409 conflicto como email repetido; 201 creado con URL del recurso.
